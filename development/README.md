# Внутренние материалы Binary GIN Editor

Пользовательское руководство ведётся на сайте Octane. Инструкция установки
пакета находится в [README](../README.ru.md). Здесь описана сборка из исходников.

## Структура

| Путь от корня проекта | Назначение |
| --- | --- |
| `src/bgin_json/` | Конвертер, локальный протокол, предпросмотр и MCP. |
| `vscode/` | Расширение VS Code, его манифест, интерфейс и проверки. |
| `schemas/` | Схема редактируемого JSON. |
| `tests/` | Проверки преобразования и рендера. |
| `tools/` | Внутренние средства исследования, проверки и подготовки выпуска. |
| `examples/` | Проверочные примеры и `mcp-settings.json`; не включаются в выпуск. |
| `build/` | Временные результаты, контрольные копии, история сборок и локальные входы. |
| `dist/` | Текущий VSIX, подготовленная папка выпуска и ZIP для передачи. |
| `graphify-out/` | Внутренний граф проекта. |

## Сборка и проверка

Из корня проекта выполните `python tools/build_nuitka.py --target <цель>` с CPython
той же архитектуры и ОС. Сборка Windows использует MSVC, macOS — Xcode, Linux —
GCC и `patchelf`. Снимок независимого кодека включён в `vendor/bgin_core`.
Параметр `--output` размещает Nuitka, кэш и результаты на выбранном диске.
Если он задан, укажите в `BGIN_BACKEND_DIR` путь к `bgin_backend.dist` внутри
этого каталога. Из `vscode/` выполните `npm ci`, `npm run check` и `npm run build`.

Проверка интерфейса — `npm run test:ui`, настоящий Extension Host — `npm test`.
Путь к установленному VS Code можно задать через `BGIN_VSCODE`. Обе проверки
используют скомпилированный модуль. Для проверки готового VSIX распакуйте его и передайте путь
к папке `extension` в `BGIN_EXTENSION_PATH`.

Из корня проекта запустите `python -m unittest discover -s tests -v`. Укажите
в `PYTHONPATH` каталоги `src` и `vendor` через разделитель вашей ОС. Дополнительные зависимости
MCP и браузера нужны только для соответствующих проверок. Изменения документации
не требуют полного корпуса BGIN.

## Подготовка выпуска

1. Обновите версию расширения и lock-файл.
2. Соберите пакет командой `npm run package` из `vscode/`. Она добавляет к имени
   VSIX целевую платформу из результата Nuitka.
3. Из корня выполните `python tools/smoke_vsix.py dist/<имя>.vsix`, затем
   `python tools/prepare_release.py --target <цель>`. Чтобы добавить ресурсы
   предпросмотра, передайте `--resources <корень-ресурсов>`. Инструмент проверяет состав
   VSIX и формирует папку с установочным пакетом, README на двух языках, условиями,
   уведомлениями о зависимостях и контрольными суммами, затем ZIP этой папки.
4. Проверьте готовый VSIX в отдельном Extension Host. Это не публикация:
   размещение на сайте и объявление выпуска выполняются отдельно.

Если при сборке ZIP указаны ресурсы, в него входят папки `gui`, `textures_android`, `texter_fonts`,
а также готовый `Preview.code-workspace` с относительными путями. Другие каталоги
архива игры не копируются. Исходное дерево проекта, исследования, тесты, граф,
виртуальная среда и прежние сборки в ZIP не попадают. VSIX содержит
`bgin_backend.exe` на Windows или `bgin_backend` на macOS и Linux, библиотеки
среды выполнения, данные каталога и лицензии.

Ручной процесс GitHub Actions **Native VSIX packages** собирает девять пакетов
на соответствующих платформах и проверяет каждый упакованный модуль без Python
в `PATH`. Запустите процесс на вкладке **Actions**. Linux собирается в Debian 12,
Alpine — в Alpine 3.23. Контейнер `linux-armhf` выполняется через QEMU.
