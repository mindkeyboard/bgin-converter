# Binary GIN Editor 0.6.2

Практическое руководство к исходникам выпуска 0.6.2. Расширение 0.6.2
использует двоичный модуль 0.6.0. [Пользовательское руководство](https://octane-loader.utmsoft.ru/ru/guide/octane-devtools/bgin-editor/v0.6.2/).

## Просмотр открытого экрана в 0.6.1

После ручного обновления предпросмотра переключатель «Вид» предлагает обычную
композицию, разнесённый вид и рентген. Разнесённый вид помещает ветки текущего
экрана рядом; «Глубина разделения» позволяет разделить их подробнее. Родительская
отрисовка получает отдельную ячейку, а геометрия детей сохраняет исходный расчёт.
Это инструмент обзора, а не имитация игрового состояния.

Ползунок «Скрыть верхние слои» убирает объекты с конца порядка отрисовки.
Он считает нарисованные объекты, а не предполагаемые логические слои движка.
«Сбросить вид» возвращает композицию. Обзор охватывает весь открытый экран,
даже если в дереве выбран отдельный объект. Обычный режим сохраняет прежний
фильтр выбранной ветки. Все эти действия используют готовый рендер, не меняют
BGIN и не запускают повторную отрисовку. После изменения ресурсов или документа
нужно снова вручную обновить предпросмотр.

Кнопка с именем экрана открывает отдельное окно выбора. Доступны поиск по имени
и типу, представления «Все» и «По префиксам», фильтр префиксов. Префиксы
вычисляются из имён с учётом разделителей и CamelCase, включая все обнаруженные
группы. Выберите строку и нажмите «Открыть» либо дважды щёлкните по ней.


## Файлы и режимы

Редактор определяет режим открываемого BGIN и показывает его рядом с названием.
Обычное сохранение удерживает исходный режим. Новый файл предлагает ~0.0.2,
~1.6.0, ~3.7.0 или ~5.8.0. Для другого режима используйте конвертер в левой
панели, направление BGIN → BGIN и явный целевой формат. Не меняйте `format`
в JSON вместо конвертации: это может потребовать преобразования самих данных.

Все четыре режима принадлежат одной семье BGIN. В новых версиях отличаются
каталог, запись свойств и анимации, поэтому универсального двоичного файла
для всех версий нет. Альтернативные значения 5.8.0 и неподходящие каналы
анимации нельзя молча отбросить ради старого режима.

На полученных входах поддержаны 70 из 74 файлов 3.7.0, 10 из 13 файлов
мини-игры 5.8.0 и 85 из 96 файлов основного GUI 5.8.0. Остальные явно
отклоняются. Причины и перечень находятся в
[исследовании форматов](research/bgin-versions-and-mcp-ru.md).

## Ресурсы из части zdata

1. Откройте BGIN и нажмите **Resources**.
2. В автозаполнении выберите **Unpacked zdata / Play Asset Delivery**.
3. Укажите папку `zdata`, `files` или `assetpacks` из распакованного установщика.
   Можно указать и готовую папку `assets/data`.
4. Проверьте GUI, текстуры и шрифты и сохраните пути.

Полная игра не нужна. Можно оставить только `gui`, нужные шрифты и нужные
`textures*.jpk`, сохранив их относительную структуру. Например:

```text
zdata/
  files/assetpacks/
    common_pack/<версия>/<ревизия>/assets/data/
      gui/                  # Нужные BGIN; обычно также widgets и sprites.
      texter_fonts/         # Только нужные шрифты.
    textures_pack1/<версия>/<ревизия>/assets/data#tcf_astc/
      textures1.jpk         # Только используемые пакеты.
```

Либо выберите три независимые папки вручную. В поле текстур можно указать
папку с распакованными текстурами, с JPK или корень `assetpacks`. JPK читаются
по запросу, исходники не меняются. Отсутствующий ресурс появится в диагностике.
Несколько версий `common_pack` требуют выбора конкретной папки. Два одинаковых
имени текстуры в пакетах требуют устранить неоднозначность выбранных источников.

Прежний сценарий **Extracted archive** сохранён для структуры с `gui`,
`textures_android` и `texter_fonts`.

## Отдельная конвертация текстур

Команда **BGIN: Convert Texture Separately** предлагает PVR-текстуру
(её расширение может быть `.tga`) и отдельный файл назначения для ~1.6.0.
Снятие внешнего сжатия сохраняет GPU-блоки и mip-уровни; ETC2/ASTC для старого
режима этим способом не допускаются. RGBA8 декодирует каждый mip и увеличивает
объём. Отдельный файл альфа-канала нужно конвертировать отдельно.

Для автоматизации из исходников:

```text
python -m bgin_json.texture_conversion input.tga -o output.tga --method rgba8 --target-format a8-1.6.0
```

Это проверено на компьютере. Загрузка результата игрой ещё не проверена.
Сохранение и конвертация BGIN никогда не запускают конвертацию текстур.

## MCP и вмешательство пользователя

Левая панель показывает подключённых клиентов, действия и последние события.
У клиента есть остановка текущей операции, запрет дальнейших правок и отключение.
Уже применённые правки отменяются обычной отменой VS Code.

Для адаптера MCP нужен Python с установленным из этого репозитория дополнением
`mcp`: `python -m pip install -e ".[mcp]"`. Для чтения старого Zstd v0.6
обычный готовый пакет `zstd` не подходит: установите его из исходников
с переменной окружения `ZSTD_LEGACY=1`. Сборщик встроенного модуля редактора
делает это сам; обычная работа VSIX системного Python не требует.

Нажмите **Copy client command** и используйте команду в настройках клиента MCP.
Каждому клиенту задайте своё `--client-name`. Команда ссылается на файл
подключения именно этого окна VS Code. Его содержимое включает локальный ключ
доступа; передавать сам файл в общий архив ресурсов не нужно.

Модель начинает с `bgin_editor`, читает `bgin_read` и передаёт полученную
`revision` как `base_revision` в правку с уникальным `operation_id`. Ручные
несохранённые изменения входят в этот же документ. Старый пакет правок получает
конфликт и требует перечитать текст. Подписка на `bgin://editor/state`
уведомляет клиента об изменениях; обновление контекста модели зависит от клиента.

Рендеры модели видны в отдельной галерее редактора. Изменённая ревизия помечает
прежний снимок устаревшим. Предпросмотр не запускает игру: выбор новых вариантов
свойств и цветовые каналы 5.8.0 пока не воспроизводятся.

В 0.6.2 рядом с типом каждого экрана показано число объектов: сам корень
и все вложенные объекты из children и tracks. Ссылки на внешние определения
и кадры анимации отдельно не считаются.
