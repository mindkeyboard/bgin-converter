# Работа с BGIN

Сначала вызови `bgin_editor`: ответ отличает подключённый редактор от отдельного режима. Затем прочитай существующий документ через `bgin_read`, настройки через `bgin_settings` и каталог нужного типа через `bgin_catalog`.

В подключённом режиме источник — `{"documentId":"..."}` из `bgin_editor` или `{"path":"..."}` для открытия BGIN в выбранном окне VS Code. Ответ `bgin_read` содержит `documentId` и `revision`, учитывает несохранённые ручные правки. Передавай эту ревизию как `base_revision` в `bgin_edit` и отдельный уникальный `operation_id`. Изменение сразу видно в редакторе и входит в историю отмены; сохраняет его `bgin_save(source, base_revision, operation_id)`. При конфликте перечитай актуальный документ и заново подготовь правку. Повтор того же запроса после обрыва соединения использует прежний `operation_id`; другой пакет требует нового идентификатора. Не подменяй подключённый документ присланной копией JSON и не сохраняй поверх него отдельным экспортом. Временно неверный ручной JSON возвращается как текст с диагностикой; работа по скрытой старой копии запрещена.

Для изменений подписывайся на ресурс `bgin://editor/state`; дополнительно каждый ответ содержит `editor.changes`, а `bgin_editor(action="changes")` возвращает накопленные события. Уведомления помогают клиенту перечитать документ, но не гарантируют немедленного изменения контекста уже работающей модели. Рендер подключённого документа появляется и в VS Code; устаревшие ревизии помечаются. Пользователь может остановить операцию, приостановить правки или отключить сессию. Новые файлы создаются командой VS Code; `bgin_create(node_only=true)` даёт заготовку узла для вставки.

В отдельном режиме передавай источник как `{"path":"menu.json"}` или `{"document":{...}}`, с одним из двух полей. `bgin_create` создаёт документ или узел. `bgin_edit` возвращает новую отдельную копию в памяти; сохраняет её `bgin_export`. Подключение к редактору при этом отсутствует.

Прочитай нужную справку, доступную также через `bgin_guide(topic=...)` и ресурсы `bgin://guide/{topic}`:

- [Формат JSON](references/json-format.md), тема `json-format`: при создании документа, изменении типов значений, спрайтов и анимации.
- [Объекты](references/objects.md), тема `objects`: назначение всех 31 типов, основные параметры и ограничения предварительного просмотра.
- [Композиция](references/design.md), тема `design`: при создании экрана или существенном изменении компоновки, с исполнимым примером JSON.

JSON — редактируемое дерево, а не дамп памяти. Не добавляй `type_hash`, `metadata_hex`, `sha256` или выдуманные свойства. Не удаляй непонятные сохранённые значения, явные типовые оболочки и повторные свойства. Схема кодирования, параметры загрузчика и степень воспроизведения в рендере отвечают на разные вопросы. Успешная сборка не доказывает игровой эффект поля. `Widget` и `GuiMgr` — классы движка, а не разрешённые JSON-типы.

Режимы документа: `a8-0.0.2`, `a8-1.6.0`, `a8-3.7.0`, `a8-5.8.0`. Сохраняй исходный `format`; другой режим выбирают явной конвертацией. Идентификаторы вида `#1234ABCD`, выданные кодеком, сохраняют неизвестные хеши типов, свойств и перечислений. Не придумывай новые хеши. Оболочка `{value, variants}` хранит основное и альтернативные значения свойства; `color_channels` — новые каналы кадров. Не удаляй их ради старого режима. Предпросмотр использует основные значения; выбор вариантов и новые цветовые каналы не воспроизводятся. Конвертация текстур выполняется отдельно от BGIN и не запускается при сохранении.

Используй `bgin_search` для поиска пути узла. При проверке ветви передавай полный документ и `options.selected`, например `/screens/0/children/2`: отдельный вырезанный узел потеряет размеры родителей. `screen` — индекс с нуля. Размер предпросмотра и высота экрана влияют на процентные размеры текста и контейнеров.

Большой файл сначала осматривай через `bgin_read(include_document=false, depth=1)`, затем запрашивай нужный `pointer`. Для рендера можно передать `source.path` и путь выделения, не возвращая весь JSON в разговор.

Ресурсы внешние: `assetRoot`, `bginRoot`, `textureRoot`, `fontRoot`, явные псевдонимы `bindings`. Проверь их через `bgin_resource_report`. Ссылки `/Widgets/...` и `/Sprites/...` разрешаются через подключённые документы. Не заменяй отсутствующий ресурс случайной встроенной картинкой. В подключённом режиме настройки принадлежат проекту VS Code и меняются его средствами; `bgin_settings` читает их. В отдельном режиме их можно сохранять через `bgin_settings`; относительные пути считаются от папки конфигурации MCP. `options` и `resources` в запросе рендера переопределяют настройки для одного изображения.

Для сравнения вариантов вызывай `bgin_render` с 1–36 запросами. Изображения сгруппированы по девять; номера и координаты находятся в JSON ответа. Проверяй ошибки ресурсов и предупреждения, а не только картинку. `state`, `progress`, `page`, `frame`, `scrollX`, `scrollY` — настройки предварительного просмотра, не новые свойства BGIN. Предпросмотр не исполняет обработчики кнопок и не доказывает поведение событий в игре.

Композицию строй по обязанностям: общий экран, верхняя панель, основная область, нижние действия; внутри — отдельные группы подписей, значков и кнопок. HorizontalContainer и VerticalContainer распределяют соседей, StackContainer накладывает слои, MarginContainer задаёт отступы, AspectRatioContainer сохраняет пропорции. Один StackContainer со всеми элементами не заменяет структуру. Следуй визуальному образцу пользователя: одинаковые отступы, согласованные высоты кнопок, чёткая иерархия текста и небольшое число акцентных цветов. Используй существующие стили и спрайты только после проверки их наличия. Не придумывай обязательную палитру для всех экранов.

Перед сохранением вызови `bgin_validate` и проверь рендер при целевых разрешениях. В подключённом режиме используй `bgin_save`; в отдельном — сравни варианты через `bgin_compare` и экспортируй отдельный файл через `bgin_export`. Для BGIN требуется независимая проверка через `bgin_core`, доступный серверу по `--core-path` или `BGIN_CORE_PATH` (путь к родительскому каталогу `bgin_core`). Существующий файл назначения отдельного экспорта заменяется только с `overwrite`, с сохранением резервной копии. В результате различай проверку JSON, двоичного преобразования, изображения и испытание в игре.
