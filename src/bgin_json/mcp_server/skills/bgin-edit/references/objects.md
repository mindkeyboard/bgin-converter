# Объекты BGIN

Это справочник всех 31 имён из `TYPE_NAMES`. Имена — значения `type` в JSON; они не обязательно совпадают с именами классов движка. `Widget`, `WidgetContainer`, `GuiMgr`, `LabelWidget` и `MovieWidget` сюда не добавляются. Полный актуальный набор полей и варианты перечислений запрашивай через `bgin_catalog(type_name=...)`. Каталог различает параметры, читаемые загрузчиком, формы, встречавшиеся в корпусе, и применение в рендере. Отсутствие поля в наблюдённом корпусе не доказывает запрета.

## Общие параметры

У обычных виджетов `MinSize` и `MaxSize` ограничивают размеры, `StretchFactor` задаёт вес распределения места, `Visible` управляет видимостью, `Enabled` — доступностью, `RenderLayer` — слоем рисования. Вес не является процентом: в линейной группе `[1,2]` означает отношение весов 1:2 с учётом минимумов и максимумов. Ресурс изображения сам по себе не гарантирует ненулевого минимального размера виджета `Movie`.

`Size` задаёт размер, который родительская компоновка может затем изменить; это не замена `MinSize` или фиксированному контейнеру. Скрытый через `Visible` элемент может продолжать занимать место. Для проверки размеров смотри `include_geometry`, а не только содержимое текстуры.

Общие параметры контейнеров: `Margins` в порядке **лево, право, верх, низ**, `Spacing`, `ClipRender`, `ClipChildrenEvents`. Два последних флага разделяют обрезку рисования и обработку ввода. Рендер моделирует рисунок, а не доставку событий. Не переноси эти поля автоматически в ресурсные `Module`, `SpriteMovie`, `MovieModule`, `TextStyle`.

`SpacingPolicy`: `Mm` — величина через `pixelsPerMm`, `Factor` — процент доступной стороны. Исторические символические имена двух вариантов противоречат применению в исследованном движке: `ScreenHeightFactor` имеет код 2 и берёт **ширину** экрана, `ScreenWidthFactor` имеет код 3 и берёт **высоту**. Сохраняй точное имя и код; не исправляй их по буквальному переводу.

## Контейнеры и свободное место

| Тип | Назначение и существенные параметры |
|---|---|
| `HorizontalContainer` | Размещает детей слева направо. `SpacingPolicy`, `Spacing`, `EmptySpaceFillPolicy`, веса детей `StretchFactor`; `EnableRightToLeftLayout` разрешает обратное направление в режиме RTL. `UnnamedOption1` у политики пустого места имеет код 0 и включает распределение по весам; `ArrangeTopOrLeft`, `ArrangeCenter`, `ArrangeBottomOrRight` группируют минимальные размеры у края или в центре. |
| `VerticalContainer` | Размещает детей сверху вниз. Те же интервалы, политика свободного места и веса, применённые к высоте. Подходит для заголовка, основного содержимого и нижних действий. |
| `StackContainer` | Даёт детям общую область, накладывая слои; `Background` задаёт фон. Используй для фона и содержимого одной карточки, а порядок соседних карточек поручай линейному контейнеру. |
| `GridContainer` | Раскладывает однотипные элементы по сетке. `ColumnCount`, `Direction`, `SpacingPolicy`, `Spacing`, `ItemAspectRatioMode`, `ItemAspectRatio`. В текущем рендере альтернативный `Direction` меняет интерпретацию числа рядов/колонок; геометрию сверяй с игрой. |
| `PageContainer` | Размещает детей отдельными страницами по `Direction`. `options.page` выбирает видимую страницу только для просмотра; переход и выбор страницы в игре задаются её кодом. |
| `ScrollContainer` | Последовательность с прокруткой по `Direction`. Интервалы и веса как у линейной группы; `SnapAtChildren`, `SnapAtEdges` задают привязки, `BarBackground`, `BarKnob`, `BarVisibility`, `BarSizePolicy`, `BarSize` описывают полосу. `options.scrollX`/`scrollY` моделируют смещение; взаимодействие и поведение полосы не подтверждаются статическим изображением. |
| `ThreeCellContainer` | Три основные области: левая, средняя, правая. `LeftAspectRatio`, `RightAspectRatio` связывают ширину крайних областей с высотой; середина получает оставшееся место. Для нового интерфейса создавай три соответствующие группы; дополнительные дети не являются доказанным способом расширить число ячеек. |
| `MarginContainer` | Выделяет общую внутреннюю область детей через `MarginFactors`: проценты собственного размера в порядке лево, право, верх, низ. `5` означает 5%, не 0.05. Отрицательные факторы обнуляются, суммы свыше 100% нормируются. Обычный `Margins` не заменяет эти факторы. Учитываются ограничения размеров; детей может быть несколько. |
| `AspectRatioContainer` | Даёт всем детям общую область с нужными пропорциями. `ItemAspectRatioMode`, `ItemAspectRatio`: для кода 0 ширина/высота, для кода 1 высота/ширина. Второй вариант называется `Vertical` (`UnnamedOption3` тоже принимается). Область вписывается и центрируется. Несколько детей разрешены; отдельные осевые Alignment не загружаются этим типом. |
| `FixedSizeContainer` | Задаёт точную область детей долями экрана. `EnableFixedWidth` и `FixedWidthFactor` — процент ширины экрана, `EnableFixedHeight` и `FixedHeightFactor` — процент высоты. При одной фиксированной стороне `EnableAspectRatio` и `AspectRatio` получают другую сторону умножением. Минимум самого контейнера и выделенная детям область различаются; `StretchFactor` по-прежнему участвует у родителя. |
| `TransformContainer` | Группирует содержимое с параметрами перехода: `Delay`, `Duration`, `TransitionType`, `InterpolationMode`. Последовательность перехода в текущем рендере не воспроизведена. Не обещай анимацию только потому, что поля сохраняются. Варианты перехода: `None`, `Left`, `Right`, `Top`, `Bottom`. |
| `CoverFlowContainer` | Оформляет набор перелистываемых элементов. Загрузчик читает `Direction`, `ColumnCount`, `SpacingFactor`, `ItemMainScale`, `ItemHeightAspectRatio`. Рендер показывает приближённый статический ряд без перспективы; не добавляй `VisibleItemsCount` из внутренней реализации рендера как подтверждённое поле файла. |
| `HorizontalSpring` | Невидимый гибкий промежуток по горизонтали; регулируй `MinSize`, `MaxSize`, `StretchFactor` в линейной группе. Нужен для разделения групп, например заголовка и действий. |
| `VerticalSpring` | Невидимый гибкий промежуток по вертикали с теми же ограничениями и весом. Отделяет верхнее содержимое от нижних действий. |

## Текст и кнопки

`TestString` хранит строку для элемента; игровой код может задавать текст отдельно. Локализационный ключ сам по себе не гарантирует перевод в рендере. `TextStyle` — ссылка на оформление, а не вложенный объект CSS. Цвета стиля — векторы, обычно RGBA в диапазоне 0…1. Внешний шрифт должен быть найден в ресурсах.

| Тип | Назначение и существенные параметры |
|---|---|
| `Label` | Однострочная подпись с `TestString`, `TextStyle`, `Background`, `Alignment`, `MarginFactors`, `InvertAlignmentRTL`. `TextPolicy`: `Fit` учитывает ширину текста в минимуме; `Scroll` и `ScrollWrap` позволяют узкую область и прокрутку через `ScrollSpeed`, `ScrollDelay`. `VerticalTextPolicy`: `Default`, `HeightFactor`, `Fit` независимо управляют высотой; `HeightFactor` — процент высоты экрана. |
| `TextArea` | Многострочный текст: `TestString`, `TextStyle`, `Alignment`, `InvertAlignmentRTL`, `FontHeightFactor`. Последний — процент высоты всего экрана: 4 при 720 даёт запрос 28.8 пикселя до ограничений стиля. Доступная ширина определяет переносы и высоту; собственный запрос ширины равен нулю. Текст обрезается своей областью. |
| `TextStyle` | Повторно используемое оформление текста в библиотеке шаблонов. `FontName`, `FontHeight`, `Style`, `PrimaryColor`, `SecondaryColor`, `ColorMode`, `ShadowColor`, `ShadowThickness`, `OutlineColor`, `OutlineThickness`. `FontNameRU` и другие языковые варианты, `FontScalingRU` и подобные задают замены и масштаб. Пара `FontHeight` задаёт границы размера; не считай любую его форму пикселями. Метрики шрифта в просмотре приблизительны относительно игрового Texter. |
| `Button` | Текстовая кнопка на основе Label. Кроме параметров подписи: `PressedBackground`, `DisabledBackground`, `ToggledBackground`, `DisabledToggledBackground`, `ToggledPressedBackground`, соответствующие `PressedTextStyle`, `DisabledTextStyle`, `ToggledTextStyle`, `Toggleable`, `TouchAreaGrowFactors`, `ButtonEventPolicy`. Фон обычного состояния — `Background`. Игровое действие подключает контроллер; BGIN не задаёт произвольный `onClick`. |
| `CompoundButton` | Кнопка с отдельными дочерними поддеревьями для состояний. Загрузчик ищет точные имена `normal`, `pressed`, `toggled`, `toggled_pressed`, `disabled`, `disabled_toggled` и назначает найденные узлы соответствующим состояниям. Внутри каждого состояния можно сгруппировать текст, значки и фон. Загружаются параметры контейнера/виджета плюс `Toggleable`, `ButtonEventPolicy`. Рендер пока показывает детей как общую группу и не доказывает правильность переключения состояний. Не переносить автоматически фоновые/текстовые поля обычной Button. |
| `ThreeCellButton` | Текстовая кнопка с боковыми секциями. Параметры Button и Label плюс `LeftBackground`, `RightBackground`, их `Pressed*`, `Toggled*`, `Disabled*` варианты, `LeftAspectRatio`, `RightAspectRatio`, `LeftOverlap`, `RightOverlap`. Точное перекрытие текста секциями пока не воспроизведено. |

`Alignment` зависит от потребителя: код 0 не означает один и тот же якорь во всех типах. Например, в словаре зарегистрированы и `Center`, и `TopLeft` с кодом 0. Сохраняй вариант, код и строку из исходного файла; выбирая новый, ориентируйся на конкретный тип и проверяй результат. `ButtonEventPolicy` поддерживает `Default` и `Autopress`; это не имя функции обработчика.

У Label `TextPolicy=Fit` само по себе не означает уменьшение шрифта: оно влияет на запрашиваемую ширину. `Scroll` движет переполненную строку туда и обратно, `ScrollWrap` повторяет её циклически, а не переносит слова. `VerticalTextPolicy=Default` использует внутреннюю высоту, `HeightFactor` — процент высоты всего экрана, `Fit` подбирает размер с учётом ширины и высоты области. Ограничения `TextStyle.FontHeight` применяются отдельно. Для настоящих переносов используй TextArea. Статический просмотр показывает состояние прокрутки; он не исполняет задержки и цикл событий игры.

## Индикаторы и переключатели

| Тип | Назначение и существенные параметры |
|---|---|
| `Progress` | Линейный индикатор заполнения. Загрузчик использует общие параметры Slider: `Direction`, `NormalBackground`, `FillBackground`, также поля оформления ручки. Наличие общих полей не превращает индикатор в интерактивный ползунок. Значение в просмотре задаёт `options.progress` от 0 до 1; в игре — её код. |
| `Slider` | Линейный ползунок с `Direction`, `KnobAspectRatio`, `NormalBackground`, `NormalKnob`, `PressedBackground`, `PressedKnob`, `FillBackground`. Рендер ставит ручку по `options.progress`; перетаскивание и события не исполняются. |
| `MultiProgress` | Индикатор с несколькими каналами: `NormalBackground`, `FillBackground0`, `FillBackground1`, `FillBackground2`. Рендер показывает первый канал; реальные значения остальных каналов задаёт игровой код. |
| `CircularSlider` | Круговой регулятор: `NormalBackground`, `FillBackground`, `KnobBackground`, `KnobFactor`. В просмотре заполнение показано приближённым сектором; точная геометрия и взаимодействие требуют проверки в игре. |
| `CircularProgress` | Тип кругового индикатора из поддержанного словаря. Исследованный `LoadCircularProgress` не перечисляет параметров; не считай параметры CircularSlider автоматически подтверждёнными здесь. Рендер умеет приближённый сектор, но это отдельное свойство рендера. Для рабочего ресурса исходи из проверенного существующего примера. |
| `Switch` | Переключатель с параметрами Slider и дополнительными `EnabledTextStyle`, `DisabledTextStyle`, `EnabledMargin`, `DisabledMargin`. Рендер не воспроизводит полное внутреннее устройство и подписи, поэтому его картинка не доказывает итоговое состояние игры. |

## Рисунки и анимационные ресурсы

| Тип | Назначение и существенные параметры |
|---|---|
| `Movie` | В `ui`/`templates` показывает ресурс по ссылке `Movie`, с `KeepAspectRatio`, `Fitting` (`Fit`/`Fill`), `Alignment`. Fit вписывает целиком, Fill заполняет с локальной обрезкой; выключенный флаг растягивает по обеим осям. Не видеофайл. В `sprites` это специальная последовательность `tracks`/`keyframes` без обычных `properties`; см. формат JSON. |
| `Sprite` | Корневой ресурс атласа: `Source` указывает текстуру, `children` содержит области Module и последовательности Movie. Само имя типа не создаёт экранный виджет. |
| `Module` | Прямоугольная область атласа: `BakePosition` задаёт начало вырезки, `Size` — размеры. `HStretch`, `VStretch`, `NinePatchMode`, `NinePatchDef`, `NinePatchDefFH` управляют растяжением/девятью областями. `Position` нельзя подменять за `BakePosition`; роль сохранённого Position не установлена. Режимы Tile и границы девяти областей требуют проверки на конкретной текстуре. |
| `SpriteMovie` | Вложенное определение Movie в `children` специального Movie. `EnableRectangle`, `Rectangle` задают пользовательские границы, участвующие в геометрии ресурса. Сохраняй известную структуру, не превращай в обычный UI-контейнер. |
| `MovieModule` | Дорожка ресурса в `Movie.tracks`: ссылка `Module`, `Pivot`, `PivotArea`, `Color`; преобразования и цвет во времени находятся в `keyframes`. Сохранённый `transform` дорожки не заменяет ключевые кадры. Нестандартные `PivotArea` имеют ограниченную поддержку просмотра. |

## Основания и пределы

Имена и формы: `names.py`, `vocabulary.py`, `observed.py`, кодировщик и схема. Чтение параметров движком: `engine_catalog.py` и зафиксированные исследования `docs/render-evidence-ru.md`, `editor-0.4.2-ru.md`, `editor-0.4.3-ru.md`, `label-text-policies-ru.md`, `textarea-and-class-reference-ru.md`. Существующая статья Atlas `gin::MovieWidget` разделяет геометрию ресурса, область виджета и нулевой вклад изображения в минимум. Она основана на статическом исследовании, без новых испытаний в игре.

Рендер реализуется в `render/layout.py`, `scene.py`, `widgets.py`, `sprites.py`, `text.py`. Его предупреждения существенны: CoverFlow, круговая геометрия, Switch, MultiProgress, переходы, часть выравниваний и поведение ввода воспроизведены частично либо не воспроизведены. Статическая картинка и проверка кодирования не заменяют испытание в игре.
