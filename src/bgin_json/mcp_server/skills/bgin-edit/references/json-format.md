# Формат редактируемого JSON

Старый вариант со строковыми именами определяется автоматически и содержит
`"format": "legacy"` в корне документа. Сохраняй это поле: оно выбирает исходную
бинарную сериализацию при записи. Без него используется поздний формат с хешами.
`format` не задаёт версию игрового движка или правила раскладки. В legacy сохраняй
буквальные имена неизвестных типов, свойств и enum; не переименовывай их по сходству.
Для enum старого формата сохраняй `value`. Пустой файл по-прежнему имеет вид
`{"screens": []}` и не получает поле `format`.

Именованный документ имеет `name` и `screens`. Явно выбирай `dialect`: `ui` для интерфейсов, `templates` для библиотеки шаблонов, `sprites` для атласов и анимаций. Для сборки именованного документа нужен хотя бы один корень. `screens` — имя массива корней во всех трёх диалектах, даже если корень представляет ресурс. Безымянный пустой черновик имеет вид `{"screens": []}` и соответствует нулю байтов BGIN: поле `name` отсутствует. Его можно хранить, читать, проверять и экспортировать с предупреждением. Не подставляй имя файла или `Untitled` автоматически. Перед добавлением объектов явно задай непустое `name`; VS Code требует его до редактирования. Пустая строка имени не заменяет отсутствие поля. Рендер пустого черновика недоступен.

Обычный узел: обязательные `type`, `name`; необязательные `properties`, `children`, `transform`. Имена типов регистрозависимы; список возвращает `bgin_catalog`. `transform` содержит пять чисел, по умолчанию `[0,0,0,1,1]`. Сохраняй исходную пятёрку. Для обычного интерфейса доказанное применение позиции не означает поддержку вращения и масштаба всего дерева; раскладка родителя также может определять положение. Для анимационной дорожки преобразование задают ключевые кадры.

## Свойства и типовые оболочки

Обычно свойства — объект: `{"Visible":1,"MinSize":[80,30]}`. Флаги BGIN — числа `0`/`1`, не JSON `false`/`true`. Тип значения определяется словарём поля, а не только видом JSON. Например, `Margins` — последовательность чисел, `MinSize` — вектор; одинаковые массивы на экране не обязательно одинаково кодируются.

| Форма | Значение |
|---|---|
| `12`, `"hello"`, `[1,2]` | Краткая форма, тип выводится по имени свойства |
| `{"enum":"Fit"}` | Зарегистрированный вариант перечисления именно этого свойства |
| `{"enum":"Center","value":4,"text":""}` | Явные числовой код и строка; сохранять при чтении |
| `{"number":12}`, `{"number":[1,2]}` | Одно число или последовательность чисел |
| `{"vector":[1,2]}` | Один вектор |
| `{"vectors":[[1,2],[3,4]]}` | Несколько векторов |
| `{"string":"hello"}`, `{"string":["a","b"]}` | Строка или последовательность строк |
| `{"path":"/Widgets/body"}`, `{"path":["/Sprites/a","/Sprites/b"]}` | Ссылка или последовательность ссылок |
| `{"enums":[{"enum":"Fit"},{"enum":"Fill"}]}` | Последовательность перечислений |
| `null`, `{"empty":2}` | Пустое значение с нулевым либо явным счётчиком |

Не меняй явную оболочку только ради сокращения. Несколько свойств с одинаковым именем записываются массивом объектов с одной парой в каждом:

```json
{"properties":[{"Visible":1},{"Visible":0},{"Margins":[4,4,2,2]}]}
```

Порядок и оба значения сохраняются при преобразовании. Рендер сводит такую последовательность к последнему значению имени; это не основание удалять ранние значения из файла. Не добавляй произвольные имена свойств: кодировщик принимает поддержанный словарь. `UnnamedProperty*` сохраняют исходные данные, но их смысл не установлен.

`enum` — символический вариант, `value` — его целочисленный код, `text` — сохранённая строка. Не угадывай код по порядку в списке. Каталог `choices` даёт зарегистрированные варианты. Незарегистрированный вариант требует явного кода; новое неизвестное имя также требует совпадающего `text`. Допустимость кодирования такого значения не подтверждает его смысл для игры.

## Ссылки

Ссылка вида `/Widgets/body` начинается с имени документа либо настроенного псевдонима. Это не абсолютный путь файловой системы. `Source` у `Sprite` указывает внешний файл текстуры. `TextStyle`, `Background`, `Movie`, `Module` связывают объекты с библиотеками. Папки и `bindings` задаются серверу отдельно; сначала проверь наличие ссылок через `bgin_resource_report`.

## Спрайты и анимация

В `sprites` корень `Sprite` содержит `Module` — области текстуры — и `Movie` — последовательности дорожек. Такой `Movie` имеет специальную форму: **без `properties` и `transform`**, с `tracks` и необязательными `children` типа `SpriteMovie`. `settings` — четыре сохранённых целых числа; значения по умолчанию кодировщика `[30,0,3333,0]`. Смысл всех четырёх чисел здесь не установлен; не называй их скоростью кадров или длительностью без дополнительного основания.

Каждая дорожка в `tracks` имеет `type: "MovieModule"`, `name`, `properties`, `keyframes`. `marker` — сохраняемый байт, по умолчанию `101`; не меняй без основания. Ключевой кадр требует `frame` (целое 0…4294967294), остальные каналы необязательны:

- `position: {"value":[x,y],"interpolation":1}`;
- `rotation: {"value":0,"interpolation":1}`; рендер трактует угол в радианах;
- `scale: {"value":[sx,sy],"interpolation":1}`;
- `colors: {"Color":[r,g,b,a]}` — формат свойств, обычно компоненты 0…1;
- `strings: ["first","second"]` — две сохраняемые строки;
- `event: {"name":"event_name","arguments":[0,0,0]}` — два uint32 и один байт. Предпросмотр не исполняет события.

Код `interpolation` канала: `0` — ступень, `1` — линейная, `2` — smooth, `3` — smoother, `4–6` — quadratic in/out/in-out, `7–9` — quartic in/out/in-out, `10–12` — octic in/out/in-out. Это байт канала, **не** числовой код одноимённого свойства `InterpolationMode` у контейнера переходов. Цвета в рендере интерполируются линейно; события и строки сохраняются, но не исполняются.

Полный пример структуры, пригодный для кодирования. Для изображения нужен внешний `atlas.png` размером не менее 32×32 в настроенной папке текстур:

```json
{
  "name":"DemoSprites",
  "dialect":"sprites",
  "screens":[{
    "type":"Sprite","name":"atlas",
    "properties":{"Source":"atlas.png"},
    "children":[
      {"type":"Module","name":"tile","properties":{"BakePosition":[0,0],"Size":[32,32]}},
      {"type":"Movie","name":"pulse","tracks":[{
        "type":"MovieModule","name":"tile_track",
        "properties":{"Module":"/DemoSprites/atlas/tile","Pivot":[0,0],"PivotArea":{"enum":"CenterArea"}},
        "keyframes":[
          {"frame":0,"position":{"value":[0,0],"interpolation":1},"scale":{"value":[1,1],"interpolation":1},"colors":{"Color":[1,1,1,1]}},
          {"frame":20,"position":{"value":[16,0],"interpolation":1},"scale":{"value":[1.2,1.2],"interpolation":1},"colors":{"Color":[1,1,1,0.5]}}
        ]
      }]}
    ]
  }]
}
```

В UI-диалекте ссылку на эту последовательность показывает обычный узел:

```json
{"type":"Movie","name":"badge","properties":{"Movie":"/DemoSprites/atlas/pulse","KeepAspectRatio":1,"Fitting":{"enum":"Fit"}}}
```

## Изменения по JSON Pointer

Путь `/screens/0/children/1/properties/TestString` выбирает свойство второго ребёнка первого корня. В именах ключей `/` экранируется как `~1`, `~` как `~0`. Для повторных свойств путь включает индекс пары: `/screens/0/properties/1/Visible`. `bgin_edit` принимает `add`, `replace`, `remove`, `test`; добавление в конец массива использует `/-`. Пример операции: `{"op":"replace","path":"/screens/0/name","value":"main"}`. Передавай весь документ; возвращённый документ используй в последующих вызовах. Изменение в памяти не сохраняет файл.

Основания формата: `schemas/bgin-json.schema.json`, `src/bgin_json/parser.py`, `writer.py`, `vocabulary.py`; представление анимации — `render/sprites.py`. Схема JSON не заменяет проверки кодировщика: он дополнительно проверяет диалект и длины каналов.
